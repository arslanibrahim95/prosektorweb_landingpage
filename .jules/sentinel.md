## 2024-04-27 - Exposed Vite API Key in `define` Configuration
**Vulnerability:** The `vite.config.ts` had secrets injected into the client bundle through the `define` property (e.g., `process.env.GEMINI_API_KEY`), which permanently embeds secrets into the compiled frontend JavaScript bundle where they can be trivially extracted by end users.
**Learning:** Adding secrets to the frontend bundle exposes them. A proper solution isn't just removing the config; if those keys were actively used, the client code making those calls would also need to be refactored to call a backend proxy. However, in this case, a codebase search revealed the keys weren't even being used by the frontend client code anymore, leaving them injected needlessly.
**Prevention:** Never use Vite's `define` or `import.meta.env` for sensitive secrets (API keys, database passwords). Always verify if the exposed secret is actually in use. If it is, migrate the logic to the backend; if it's not, just delete the injection point from the Vite config entirely.

## 2025-10-27 - Remove Hardcoded Secrets from Configuration

**Vulnerability:** Hardcoded `GEMINI_API_KEY` was exposed in `frontend/vite.config.ts` via `process.env.API_KEY` and `process.env.GEMINI_API_KEY` defines.
**Learning:** Exposing API keys via `define` in Vite configurations effectively hardcodes these keys into the resulting client-side JavaScript bundle, making them accessible to any user who inspects the application code. This can lead to unauthorized API access and potential quota exhaustion or financial loss. It's crucial to only expose non-sensitive public keys or configuration if absolutely necessary, and to keep sensitive operations and their associated secrets safely on the server side. In this case, `GEMINI_API_KEY` wasn't even being used by the application, yet was being exposed.
**Prevention:** Do not expose sensitive API keys in the Vite `define` configuration. If client-side code requires configuration, use `VITE_` prefixed environment variables, and ensure they do not contain sensitive secrets. Review Vite `define` configurations periodically to ensure no secrets are inadvertently injected into the build. Use a linter or secret scanning tool in the CI/CD pipeline to catch potential leaks before they are committed.

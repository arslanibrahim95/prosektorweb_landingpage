## 2024-05-18 - Semantic HTML for Core App Interactions
**Learning:** In highly stylized React components like `WelcomeScreen` and `MockupScreen`, there's a strong temptation to use generic `<div>` elements with `onClick` handlers for complex, multi-layered buttons (e.g., buttons containing gradients, multiple text lines, and floating SVGs). This severely breaks keyboard accessibility, as users relying on the Tab key or screen readers cannot navigate to or activate these "buttons" using Space/Enter.
**Action:** Always replace interactive `<div>` elements with semantic `<button>` elements, even if they require custom styling to reset browser defaults (like `border-none bg-transparent`). Furthermore, when adding complex decorative elements (like floating/bouncing SVGs) inside buttons, always add `aria-hidden="true"` to prevent screen readers from attempting to announce redundant or confusing nested content.
